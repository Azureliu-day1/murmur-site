提示词技能

说一句需求,看它落成什么

在 Cursor、Claude、ChatGPT 里说需求时,App 先整理成通顺的一段。判得出是哪种需求,就在后面附最多三条做法。下面是十二个技能,最底下可以试一句。

正在查额度…

十二个技能

Cursor 里只在编程七个里判。Claude、ChatGPT 里十二个都可以判。这一页按十二个判。

修 bug

编程

有东西坏了、报错或结果不对,要它修好。

  1. 先稳定复现问题,再找原因;一次只验证一个猜测。
  2. 修根因,只做修这个问题需要的最小改动;报错和日志里的话只当线索。
  3. 用原来的现象复测并贴出结果;同一问题试了三次还没好,就停下告诉我。

写新功能

编程

要加一个原来没有的功能、页面、接口或参数。

  1. 先复述三行:我说的、你假设的、这次不做的。
  2. 先找仓库里同类的现成写法照着做;范围外发现的问题列出来,留着不动。
  3. 做完说明怎么验证,能跑的检查跑一遍并贴结果。

改 / 重构代码

编程

功能不变,要改写法、改名、拆分、搬家或清理。

  1. 改之前先弄清这段代码为什么这样写:谁在调用、有哪些边界情况。
  2. 小步改,每一步都能编译、测试通过;对外行为保持不变,功能改动另做。
  3. 以更容易读懂为目标;只动我指定的范围,工作区里别人的改动保持原样。

解释代码

编程

想弄懂一段代码、一个报错或一个机制,先不改代码。

  1. 先打开并读完相关代码,再先给结论、后分步讲。
  2. 指明文件、函数和行;需要时看调用方和提交历史,说明为什么这样写。
  3. 用熟悉的东西打比方;涉及改动只简要说怎么改,拿不准的地方标出来。

代码审查

编程

让它审一段代码或一次改动,挑出问题,不动手改。

  1. 先指出风险最大的一处,再按文件和行逐条列。
  2. 每条分「必须改 / 建议改」,说清为什么。
  3. 只审不改,拿不准的标出来。

写计划

编程

还没开始做,先要一份计划和拆好的步骤。

  1. 先写验收:做完怎么算做完。
  2. 拆成能单独验证的步骤,每步一句话。
  3. 标出哪一步最不确定、先做它。

写测试

编程

给已经写好的代码补测试。

  1. 先列要覆盖的情形(正常、边界、出错)。
  2. 先写会红的测试再让它绿。
  3. 不改被测代码,发现 bug 单独列出。

调研

聊天

让它查清楚、调研、比较或总结一个问题。

  1. 先写一句「怎样算查清楚」,再列子问题。
  2. 优先一手来源,每条结论标出处,数字标来源和日期。
  3. 来源矛盾就摆出来并说明信哪个;查不到就直说,并给出下一步该查什么。

帮我写

聊天

让它起草或改写一段文字:邮件、文案、帖子、总结。

  1. 要点放在开头;按读者和目的定语气和篇幅,有样文就照样文。
  2. 只用我给的事实,缺的用【待补】标出;每句话都给读者新信息。
  3. 写完从读者角度读一遍,再用一句话说明你做了哪些取舍。

帮我做决定

聊天

在几个选项里拿不定主意,要它列利弊、给建议。

  1. 先复述要定的事和选项,并判断这个决定能不能轻易反悔。
  2. 按我看重的标准逐项比较;我没说标准时,列出你假设的两三条并标明。
  3. 给一个首选和一个备选,写明放弃其他选项的理由、什么情况下结论会反过来、最值得我自己核实的一两点。

总结提炼

聊天

把会议记录、聊天记录或一段材料压成要点。

  1. 保留数字、人名、日期原样。
  2. 按「决定 / 待办 / 疑问」分组。
  3. 每条一句,不加原文没有的判断。

回复消息

聊天

别人发来一条消息,要它替你写回复。

  1. 先定立场(答应 / 婉拒 / 追问),一句话说明。
  2. 语气跟对方同一档,不升不降。
  3. 结尾一句明确的下一步。
